# 保存位置与交付

第 0 步先确定素材目录和本轮报告工作区，再委派子代理；所有子代理使用主 Agent 传入的绝对路径，不自行另建工作区。

- **数据**：共享论据表直接保存为 `素材目录/structured_data.json`，不额外添加 `source/`；原始素材不修改。
- **工作区**：用户指定位置优先，否则在 `素材目录/报告/报告主题-日期时间/` 创建本轮目录，不默认使用 WorkBuddy 会话目录。多处素材没有明确保存位置，或目标不可写时，先确认，不静默换目录；新任务不覆盖已有同名目录。

默认完整目录如下。本轮报告工作区是用户项目文件夹下的 `报告/<报告主题-日期时间>/`，后续执行卡中的路径均相对此工作区；用户指定其他保存位置时，保持工作区内部结构不变。

```text
用户项目文件夹/
├── 原始素材……
├── structured_data.json
├── 数据版本说明.md
└── 报告/
    └── <报告主题-日期时间>/      日期指开始时间
        ├── <报告主题>.md         终稿报告
        ├── 历史版本/
        │   ├── <报告主题>-v0.md
        │   ├── <报告主题>-v1.md
        │   ├── <报告主题>-v2.md
        │   └── 版本说明.md       每版记录所用数据版本
        └── Agent运行记录/
            ├── 本轮需求.md
            └── 评测与改写记录/……
```

日期时间在本轮开始时确定，后续改写不改目录名。用户确认原文统一保存到 `Agent运行记录/本轮需求.md`；只引用素材目录的 `structured_data.json`，不在 Agent运行记录中保存数据快照或旧数据备份。`数据版本说明.md` 保存 D1、D2…、更新时间、更新内容、数据指纹，以及当前素材指纹清单；不另外生成 `素材清单.json`。扫描素材时排除这些产物、`报告/` 和指定的报告工作区。

每次 Writer 成功写出初稿或改写稿（包括用户反馈直接修订），都保存为未占用的 `历史版本/<报告主题>-vN.md`，并立即在 `版本说明.md` 追加：报告版本、生成时间、依据的 dataVersion/dataSha256、修改摘要、是否评测及实际得分。未评测写“未评测”，不能继承旧分数。主 Agent 核验后将选定稿复制为 `<报告主题>.md`，不覆盖历史稿。旧实验没有数据版本依据时标“未知”，不得补填当前版本冒充。

交付只展示 `报告主题.md`、`历史版本/`，并简述改写轮数和最终得分；不额外生成同内容的 `final.md`、交付版或多种格式。历史稿不覆盖，轮数、分数和最佳版本记入 `历史版本/版本说明.md`，内部文件不作为交付附件。用户另有格式要求时按要求交付。

`Agent运行记录/` 是可见的过程记录目录，供查阅与恢复任务，不作为正式交付附件。恢复已有任务沿用已记录的原路径，不搬迁旧实验；本约定不改变记忆目录。
