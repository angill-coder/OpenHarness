# 保存位置与交付

第 0 步由主 Agent 确定目录，所有子代理使用传入的绝对路径，不自行另建工作区。

- **数据**：共享论据表直接保存为 `素材目录/structured_data.json`，旁边保存 `数据版本说明.md`；原始素材不修改，不额外添加 `source/`。
- **报告目录**：用户指定位置优先，否则使用 `素材目录/报告/`，不默认使用 WorkBuddy 会话目录。多处素材没有明确保存位置，或目标不可写时，先确认，不静默换目录。
- **内部目录**：同一报告使用 `报告目录/.report-agent/<报告主题-首次创建日期时间>/`；后续反馈和新 Loop 沿用该报告标识，不因新会话另建报告。同名且无法判断是否续写时，先确认或区分主题，不覆盖已有文件。

## 完整目录示例

下列 v1–v3 旁的说明只是举例，版本号不绑定某种产生方式；按实际任务创建目录，不预建空目录。

用户项目文件夹/

├── structured_data.json

            │   └── r001/               后续资料处理使用 r002……

            │       ├── judgments/

            │       │   ├── R1.json

素材处理沿用已有解析工作目录用途，不保存论据表快照或旧数据备份。`数据版本说明.md` 记录 D1、D2…、更新时间、更新内容、数据指纹及当前素材指纹清单；不另外生成 `素材清单.json`。扫描原始素材时排除这些产物、`报告/` 和指定的报告工作区。

## 版本号与目录含义

- **报告 vN**：从 v1 开始。同一报告每次交付内容有变化的新稿，取已有交付版本最大序号加一；Loop 交付和直接改写共用编号，旧版保留。正文未变只更新评测记录，不复制新报告。
- **内部候选 RN**：每轮 Loop 独立从 `R0` 初稿开始递增；被拒绝的候选也保留。RN 与 vN 没有数字对应关系。
- **Loop 目录**：`loop-序号-YYYYMMDD-HHmmss/`，日期时间在本轮开始时确定；新 Loop 新建目录，恢复时沿用。执行卡中的需求、候选和评测路径均相对此目录。

## 保存与交付

- Loop 完成后，将最佳候选发布为 `报告/<报告主题>-vN.md`；内部候选与评测明细只留在隐藏目录。
- 直接 Rewrite 基于当前交付版生成新 vN，不新建 Loop 或反馈修订记录目录。只登记成功交付的版本，旧稿不覆盖，不另存无版本号终稿。
- `版本说明.md` 记录当前版本及每版的时间、数据版本（dataVersion/dataSha256）、用户修改要求、修改摘要和评测结果；Loop 交付另记轮次、最佳 RN、改写次数及停止原因。未评测不沿用旧分数，未知信息不补猜。
- 对话只交付本次报告和简短结果，不罗列旧稿或内部文件。`.report-agent/` 在 macOS 默认隐藏，Windows 创建时设置 Hidden；无法设置不阻塞交付。

恢复已有任务沿用已记录的原路径，不搬迁旧实验；本约定不改变记忆目录。
