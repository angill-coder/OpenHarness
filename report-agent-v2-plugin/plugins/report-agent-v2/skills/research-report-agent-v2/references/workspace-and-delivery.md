# 保存位置与交付

第 0 步先确定素材目录和本轮报告工作区，再委派子代理；所有子代理使用主 Agent 传入的绝对路径，不自行另建工作区。

- **数据**：共享论据表直接保存为 `素材目录/structured_data.json`，不额外添加 `source/`；原始素材不修改。
- **工作区**：用户指定位置优先，否则在 `素材目录/报告/报告主题-日期时间/` 创建本轮目录，不默认使用 WorkBuddy 会话目录。多处素材没有明确保存位置，或目标不可写时，先确认，不静默换目录；新任务不覆盖已有同名目录。

默认完整目录如下。本轮报告工作区是用户项目目录下的 `报告/<报告主题-日期时间>/`，后续执行卡中的路径均相对此工作区；用户指定其他保存位置时，保持工作区内部结构不变。

```text
用户项目目录/
├── 原始素材……
├── structured_data.json
└── 报告/
    └── <报告主题-日期时间>/
        ├── <报告主题>.md
        ├── 历史版本/
        │   ├── v0-初稿.md
        │   ├── v1.md
        │   ├── v2.md
        │   └── 版本说明.md
        └── .report-agent/
            ├── inputs.md
            ├── evidence/……
            └── state/……
```

用户确认原文统一保存到 `.report-agent/inputs.md`。每轮采用的论据只保留一份固定快照，不另建同内容的 snapshot 文件；扫描素材时排除共享论据表、`报告/` 和指定的报告工作区，避免把产物再次当作素材。

交付只展示 `报告主题.md`、`历史版本/`，并简述改写轮数和最终得分；不额外生成同内容的 `final.md`、交付版或多种格式。历史稿不覆盖，轮数、分数和最佳版本记入 `历史版本/版本说明.md`，内部文件不作为交付附件。用户另有格式要求时按要求交付。

恢复已有任务沿用已记录的原路径，不搬迁旧实验；本约定不改变记忆目录。
