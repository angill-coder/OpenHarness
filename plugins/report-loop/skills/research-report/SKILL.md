# 调研洞察汇报报告生成

## 目的
把用户提供的异构原始素材（访谈记录、调研问卷、doc/pdf/excel、公开信息）整理成一份**面向最高管理层、可编辑的调研洞察汇报报告**。可回溯性是生命线，素材撑不起的地方诚实留白。

## 执行步骤

### 第 0 步：开场交互（**先完成这三轮，拿齐再往下；用户已在开场提供的就不必重复问，只补缺**）
1. **汇报背景**：问用户——这份汇报给谁看、要支撑什么决策、什么场合？（决定受众口吻、摘要聚焦、建议的决策指向）
2. **材料假设(hypothesis)**：问用户——你对结论的预判/想验证的假设是什么？（作为分析主线去**验证或证伪**）
3. **标注重点素材**：先 `ls` 列出所有素材文件，请用户**标出哪些是高质量/重点材料**（可让其点选或列出文件名/S-xxx）。
> 三项没拿齐（或明显含糊）就逐项追问，别自行假设。

### 第 1 步：盘点素材
列出用户指定路径或当前工作目录下的相关文件（.doc/.docx/.pdf/.xlsx/.csv 等），说明类型与主题；给每份素材/关键片段编来源号 `S-001`、`S-002`…（这些号供你**内部**把每个论断对回素材做可回溯核验；**最终报告正文不写出来源号**）。**标记出第 0 步里用户圈定的重点素材。**

### 第 2 步：解析素材
- pdf → 用 Read，或 `pypdf`/`pdfplumber` 提取文本；docx → 读 `word/document.xml`（`zipfile`+`xml`）；xlsx/csv → `pandas`/`openpyxl` 读，无库则请用户粘贴关键表。
- 抽取：关键数据、访谈原话、结论；**同时标出素材之间的口径/来源冲突**。

### 第 3 步：按规则产出报告
**产出前先 Read 本目录 `references/instructions.md`**（完整的内容规则、报告结构和三项输入用法），严格照它写。

### 第 4 步：交付
输出一份可编辑的 Markdown 报告给用户；不附带内部分析过程、写作规则说明或工具运行说明。

## 参考
- 完整写作规则、报告结构、以及"背景/假设/重点素材"三项输入的用法，见 `references/instructions.md`——**产出前必读**。
