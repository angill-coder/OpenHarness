# 总裁调研汇报 · 执行方法与质量基线

本文件给出完成报告的方法。Rubric 用于验收结果；这里关注如何稳定地产出好结果，而非逐项复述评分条款。

## 四轮输入如何影响报告

1. **汇报背景**决定唯一的决策问题、信息取舍和建议对象。报告中的每一部分都应帮助该受众作出该决策。
2. **待验证假设**用于组织验证路径。先寻找支持证据，也主动寻找反例；最终可以支持、部分支持、无法验证或证伪，不能迎合用户预判。
3. **材料重点**决定分析资源的优先级，但不能使报告隐瞒相反证据、关键冲突或用户未标注的重大风险。
4. **报告篇幅**是信息预算。优先保留核心判断、关键证据、必要口径、冲突和决策含义；压缩背景、重复和次要案例。用户给页数时按每页不超过约 1000 个中文可见字符折算，表格单元格计入，Markdown 标记和空白不计。

## 固定交付结构

按以下顺序输出，不增加“研究方法”“素材清单”“证据不足”等工作流章节：

1. **核心摘要**：不超过 3 条 bullet，每条是一项独立判断，重要结论在前。
2. **核心发现**：用结论型标题或首句展开摘要；归因和机制放进对应发现，不另建空泛分析章。
3. **启示与建议**：将风险和趋势放进相关行动语境；建议与前文问题、证据和机制相连。

标题可以适配主题，但三段功能不可缺失。正文不显示 S-xxx/C-xxx，不写“本节遵循金字塔”“按 Rubric 检查”等元说明。

## 一、先建立证据底稿，再决定写什么

写作前为候选核心判断建立内部“论断卡”，至少记录：

- 准备表达的最小论断；
- 对应素材位置和原文含义；
- 主体、时间、范围、条件和统计口径；
- 属于直接事实、素材观点、归纳判断还是因果/机制推断；
- 信源是否独立，是否存在冲突、反例或缺口；
- 这项判断对管理层决策有什么意义。

这样做的目的，是让报告从证据中生长，而不是先写一个顺滑结论，再回头寻找能够支持它的片段。

### 证据准入原则

- **事实闭集**：任何事实、数字、案例和结论都必须能回到素材核验。素材没有提供的内容不能用常识、推算或语言润色补入。
- **忠实转述**：不得改变主体、方向、范围、条件、时间状态、统计对象、口径或确定性。尤其警惕把局部写成整体、个案写成普遍、累计状态写成当期变化、相关写成因果、用户重合写成迁移或替代。
- **确定性匹配证据强度**：权威统计面板或权威原始记录中的直接事实可以单源陈述；访谈、个案或单一模态支撑的归因、机制和普遍性判断，应限定主体与范围，必要时降级为观察或待验证方向，但不机械贴“单一信源，待验证”标签。
- **冲突不抹平**：素材在事实、口径或结论上冲突时，具体说明冲突在哪里、为何不能合并，以及当前采用什么边界。不能笼统写“口径略有差异但方向一致”，也不能无说明地选择更有利的一方。
- **不足不强答**：证据无法回答时，不输出确定答案。若缺口影响决策，把它转译为“当前能够判断什么、不能判断什么、缺口如何影响决策、下一步验证什么”；低价值缺口直接省略。
- **数字先过口径**：使用比例、区间、频率、增速和比较前，核对统计对象、分子/分母、时间范围、单位和对比基准。异质口径不能拼成精确区间或统一排名。

### 五条不可突破的红线

1. 不写无据事实或关键论断，不编造素材外信息。
2. 不曲解素材原意，不偷换主体、时间、范围和口径。
3. 不把相互冲突的素材混用成一致结论。
4. 不在证据不足时强行作答。
5. 不使用“不是……而是……”句式，不用“数据驱动、闭环、赋能、范式重构”等空词代替具体判断。

命中任何红线都应返工，不通过增加免责声明掩盖问题。

## 二、先确定决策主线，再组织章节

把报告压缩成一句话：**管理层需要对什么问题形成什么判断，并据此采取什么行动？** 若无法用一句话复述，说明材料仍是并列堆积，没有形成故事线。

从证据底稿中选择不超过 3 项核心判断。选择标准依次是：

1. 与用户要支撑的决策直接相关；
2. 证据强度足以承载表达的确定性；
3. 相比原始材料具有提炼增量；
4. 能改变优先级、资源配置、风险判断或下一步行动。

为每项判断安排“判断 → 关键证据 → 原因或机制 → 边界/反例 → 决策含义”。章节之间形成递进、因果或分析步骤上的承接，不以 MECE 为名机械切块，也不拼接若干互不关联的结论。

每项核心发现都要回答 so what：它改变了什么判断，为什么现在值得关注，对管理层意味着什么。素材没有真实冲突时不要制造戏剧性；可以呈现差异、取舍、约束、反常或边界。

摘要只保留这不超过 3 项核心判断，并与正文逐项对应。正文可以补充次级证据，但不能另起一套主结论。

## 三、在证据边界内形成洞察

洞察是比材料复述多走一步，但不能跨过证据边界。

- **提炼规律时**：至少比较多个可比证据，说明共性及适用边界；孤立案例只能作为案例，不能代表总体。
- **解释原因时**：区分事实、受访者解释、相关关系和因果机制。只有素材真正支持时才作归因；否则保留为可能机制并说明依据。
- **判断趋势或风险时**：核对时间序列、样本范围和异常点。一次性波动、短窗口或离群点需交叉验证或情境解释，不能直接写成持续趋势或未来必然；必要时标明判断强弱。
- **提出建议时**：从已识别的问题和机制出发，说明动作为什么可能有效、由谁做、优先解决什么、用什么信号验证。素材无法支持具体方案时，提出验证路径，不跳到宏大建设方案。

不要为了形式完整，强迫每个发现同时出现归因、趋势和建议。只在任务和证据需要时使用相应分析。

## 四、写成可直接汇报的终稿

### 结论先行、易于扫读

- 摘要不超过 3 条，直接写判断，不写背景、研究过程或材料说明。
- 每章用标题或首句给出中心判断，再放证据和解释。
- 每段或 bullet 承载一个核心意思；明显并列、递进或多层信息拆分。避免四句以上长段，也不要用 bullet 包装长段。
- 相同主体、背景、单位、口径和限定条件集中表达，删除无信息增量的重复。

### 有比较价值时才使用表图

多对象、多指标或跨时间比较优先用 Markdown 表格；单一事实不必为形式强行做表。表图应能独立理解：

- 给出清晰标题，必要时编号；
- 标清对象、指标、时间、单位、口径及必要注释；
- 可比对象使用一致字段；不可比时明确原因；
- 单元格不能无说明留空，使用“未采集”“不适用”等准确状态；
- 每个数值仍必须来自素材，不补数，不把不可比数据拼成统一排序。

### 使用终稿语言

- 定义首次出现的专业术语、缩写、组织特有称谓和“内部”等相对指代。
- 写清百分比、区间、频率、峰值、内外部归属和适用范围，消除指代歧义。
- 删除“待复算”“单一信源待验证”“素材不足以恢复统一口径”“证据不足建议补充研究”等中间工作流标签；保留真正影响决策的边界，并写成管理层可理解的判断和验证动作。
- 建议必须具体，避免“继续关注、加强重视”等无法执行的表达。

### 守住篇幅预算

报告完成后按用户口径复算长度。超限时依次删除重复、背景、低优先级案例和不影响判断的过程信息；不能以压缩为由删除关键问题、关键 Claim、必要口径、冲突或证据边界，也不能为凑满篇幅注水。

## 五、交付前进行一次逆向核验

不要机械朗读所有规则；按以下顺序验证最可能造成失败的问题：

1. **逐项反查核心判断**：数字、主体、时间、范围、口径和确定性是否与论断卡一致？摘要是否比正文说得更强？
2. **挑战泛化与因果**：所有“多数、普遍、主要、持续、领先、驱动、导致”等词，是否有足够分母、时间序列或机制证据？
3. **检查冲突和不足**：重大冲突是否具体呈现？不能回答的问题是否被写成了确定结论？
4. **检查故事线与覆盖**：可回答的关键问题、必需模块和关键 Claim 是否完整？三条摘要能否在正文找到对应展开？重点问题是否获得足够篇幅？
5. **检查终稿呈现**：章节是否结论先行，建议是否与证据闭环，表图是否自解释，术语是否清楚，长段和重复是否已压缩，篇幅是否在上限内？
6. **检查五条红线**：任何一条未通过都先修正再交付。

## 六、简短正反例

**范围与证据**

- 合适：“在已访谈的 6 个团队中，4 个提到知识检索耗时；现有样本不足以判断全部团队的普遍程度。”
- 不合适：“知识检索是各团队最主要的效率瓶颈。”

**冲突与口径**

- 合适：“供应商页面以 64 人为分母，底表另有 98 条记录；材料未说明筛选关系，两组比例不直接合并。”
- 不合适：“不同来源口径略有差异，但总体趋势一致。”

**趋势与异常**

- 合适：“指标在所列期间先降后升，现有序列不支持持续回落判断。”
- 不合适：“指标持续回落，竞争热度正在减弱。”

**建议闭环**

- 合适：“先在同一问题集记录错误率、引用可用率和人工复核时长；确认改善集中在哪类问题后，再决定扩展范围。”
- 不合适：“持续建设能力并纳入重点路线图。”
