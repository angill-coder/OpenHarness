# 调研洞察汇报报告 · 写作规则与结构（产出前必读）

本文件是 `research-report` skill 的核心执行指令。产出报告时**逐条遵守**。

## 三项写作输入怎么用（素材解析后、第 1 步确认）

1. **汇报背景**（给谁/支撑什么决策）→ 决定受众口吻、摘要聚焦点、建议的决策指向。摘要和建议要直接对着这个决策说话。
2. **摘要观点假设 hypothesis** → Agent 基于已解析素材认真思考，主动提出 1–3 条完整判断，请用户确认、补充或调整；用户也可以直接给出自己的 hypothesis。合格的 hypothesis 脱离材料标题后仍能单独读懂，能够回答“对什么作出什么判断，以及为什么或意味着什么”，而不是名词组合、章节主题或几个关键词。确认后的 hypothesis 用作分析和摘要写作主线，最终明确给出**支持 / 反驳 / 部分成立**的判断。
   - 向用户展示完整判断，不要为了适配多选框压缩成短标签；交互控件不适合时，使用编号文本逐条确认。
   - ⚠️ **必须遵守**：hypothesis 只是待检验的假设，**不是要迎合的结论**。素材不支持就如实说"假设未被证实/被证伪"，**绝不为了迎合预判去编证据或过度解读**（违反可回溯性）。诚实证伪比勉强证实更有价值。
3. **重点素材**（用户圈定的高质量材料）→ 核心结论优先建立在这些材料上；非重点材料降权或仅作佐证；用户没圈的、明显无关的按噪音处理（呼应下面"剔噪 + 信源充分"）。

## 报告结构（面向高管，三部分，按此顺序）

1. **核心摘要**：≤3 条 bullet，**每条直接写结论**（不是背景/过程），按重要性排序（最重要在前）。
2. **核心发现**：关键事实/数据，每条都必须有明确素材支撑（写作时你自己对回 `S-xxx`/`C-xxx` 核验，但**正文不写出来源号**）；**把"为什么"（归因）直接融进对应发现里**——每条发现在给出现象的同时说清成因，不单列"归因分析"章节。
3. **对我们的启示与建议**：可执行的策略启示；**把趋势判断/风险融进相关建议处**（给趋势要标置信度、不外推未来），不单列"趋势判断"章节；具体动作若素材无数据支撑，诚实说"素材不足、建议补充后再定"。

- **不要**单列"归因分析""趋势判断""素材清单/附录"等章节——归因融进发现、趋势融进启示；**正文不写来源号（不出现 `[S-xxx]`/`[C-xxx]`），也不放素材清单**——但每条论断背后都必须真有素材支撑、能在核验时回溯到具体来源。
- 可按实际主题给三部分起更贴切的小标题，但"结论先行的摘要 + 含归因的发现 + 含趋势的启示建议"三段核心不能少、不能多列上述被禁的独立章节。
- **不要把写作方法本身写进报告**：诸如"（结论先行）""（归因）""（金字塔结构）""本节遵循 MECE"这类元说明，是给你遵守的规则、不是报告内容——正文只出现结论、发现、建议本身，不要在标题后括注、也不要另起一行写这些原则字样。

## 本次报告任务约束

- **受众与目标**：面向总裁/最高管理层，围绕用户给定的话题形成可直接用于决策的汇报。
- **初始输入**：接收用户给定的话题与原始素材；原始素材文件只读，不修改。
- **补充交互**：完整解析素材后，确认汇报背景、摘要观点假设和重点素材；用户已提供的不得重复询问，仍缺失或含糊的由 Agent 基于素材提出建议并请用户确认，不自行猜测。
- **输出结构**：严格三段式——摘要、关键发现、启示。摘要结论先行；关键发现承载事实、数据和有据归因；启示面向决策，素材不足处明确留白。
- **素材边界**：所有结论与数据只来自原始素材，不新增、篡改或偷换事实与数据口径。允许为高管阅读做有据的筛选、压缩和重组，但关键 claim 不遗漏、噪音不充数、原意不改变。
- **图表规则**：数据密集或多组对比处优先用 markdown 表格或清晰图表；图表中的每个数字仍须来自素材，禁止补数或推算未给出的数值。
- **写作方式**：结论先行、金字塔展开、信息组织 MECE；正文采用“中心判断或短过渡 → 一级 bullet 分论点 → 必要的二级 bullet 证据、案例或边界”的层级结构，避免连续长段堆叠，也不把内容机械切成无衔接的扁平 bullet。

# 调研洞察汇报质量规则

## 一、硬规则

### 1. 证据与素材边界

1. 动笔前建立内部“主张—证据”清单，将拟写的事实、数字、判断、归因、趋势、风险和建议逐项对应到原始素材的具体位置。该清单用于核验，不在正文展示内部来源编号。
2. 每个事实、数据和结论都必须有原始素材支撑并可核验；不得补写素材中不存在的新事实，正文无需展示内部来源编号。
3. 转述、总结和改写必须保持素材原意，不得改变主体、方向、范围、条件、统计口径或确定性。
4. 不得通过省略关键前提、限制条件、反例或不利信息，使素材产生不同于原文的含义。允许压缩和重组，但用户指定的关键事实、关键结论及影响判断的限定条件必须保留。
5. 素材存在事实或口径冲突时必须明确说明，不得混用为一致结论，也不得无说明地只取有利一方。说明至少包括：冲突内容、各自口径或来源情境、对当前判断的影响；素材无法裁定时不得擅自裁定。
6. 访谈、个案或单一模态证据只能支持其覆盖范围内的观察或机制假设。凡据此形成的归因或机制判断，包括摘要、标题、表格结论和启示，均须使用与证据强度相称的校准表达，并就地说明样本或场景边界；不得写成整体比例、普遍规律、主因、核心机制或已获验证的确定结论。权威统计面板或权威原始记录明确记载的直接事实，可按原口径直接陈述；由该事实延伸的机制判断仍按前述要求处理。
7. 素材不足以回答的问题不得强行作答；若影响决策，应说明当前能确认和不能确认的判断以及所需验证。
8. 数字、比例、频率和区间依赖口径时，按理解需要写清对象、分子与分母、时间范围、比较基准、单位和统计口径。口径变化会影响结论时，必须说明变化方向或敏感性；素材未提供的信息不得推算或补齐。
9. 不得把相关关系写成因果关系，不得把计划、预测或受访者观点写成已发生事实，不得把区间中点、缺失值或估算值写成实测值。

### 2. 报告结构

1. 正文只设三个一级模块，并按以下顺序输出：`摘要`、`关键发现`、`启示`。三个模块都必须存在并包含实质内容，不得增加并列的第四模块。
2. 全文围绕一个明确的研究或决策问题展开。每一条内容都应服务于该问题；无法说明决策价值的背景和重复信息应删除。
3. 摘要不超过三条。每条首句直接给出一个可独立成立的核心判断，并按对管理层决策的重要性排序，不以背景、过程或材料说明开头。
4. 关键发现必须逐项展开摘要中的核心判断。摘要中的每项判断都要在关键发现中找到对应证据；关键发现中的主要结论也要能回扣摘要，避免两部分脱节。
5. 关键发现按因果关系、递进关系或清晰的分析步骤排列。每章以标题或首句表达中心判断，随后依次给出事实、数据、案例、机制解释和必要边界。
6. 启示只写能够由前文证据推出、且对决策有意义的内容。提出建议时，必须说明针对的问题或机制、建议动作及其可能有效的原因；证据不足时明确写出判断留白、决策风险和验证动作。

### 3. 金字塔与 MECE

1. 先写顶层结论，再写支撑结论，最后写事实和数据。不得先铺陈材料、再让读者自行寻找结论。
2. 同层要点必须采用同一划分维度，例如按业务环节、对象、地区或时间阶段划分；不得在同一层混用原因、结果、案例和建议。
3. 交付前检查同层要点是否相互重叠、是否遗漏素材能够支持且影响决策的重要部分。发现重叠时合并或重划边界；发现缺口时补充，素材无法支持时明确边界。
4. 同一概念、指标、人群、统计口径和时间范围在全文保持一致。确需切换时，在首次切换处明确说明新口径及其对比较的影响。
5. 呈现素材中真实存在且影响决策的差异、矛盾、反常、取舍和约束，并解释其重要性。不得为了增强故事性人为制造冲突或夸大差异。

### 4. 洞察与推理

1. 不停留在逐条复述素材。应在证据允许的范围内归纳跨案例、跨对象或跨时间反复出现的模式、共性或规律，并列出支撑该归纳的关键证据。
2. 原因或机制判断必须提供现象之外的解释增量，并能回溯到素材。素材只能证明现象时，只描述现象，不使用确定性因果措辞。
3. 趋势、未来判断和风险必须说明证据基础、适用条件和不确定性。按证据强弱使用“可确认”“较可能”“初步提示”“暂无法判断”等表述，不得制造未经素材支持的置信度或概率。
4. 异常值和离群点必须经过素材内的交叉验证或情境解释。无法验证时，将其标记为待核实，不得用单个异常点代表整体趋势。
5. 建议必须与已识别的问题或机制一一对应，能够回溯到前文证据，并说明动作为什么可能有效。素材不足以支持具体动作时，只提出验证方向，不生成空泛或确定性的建议。
6. 用户指定的全部关键事实和结论必须得到覆盖；分析深度按决策重要性分配，不以次要细节挤占关键问题篇幅。

### 5. 表达、图表与篇幅

1. 语言简洁、严谨，直接表达有决策价值的结论。删除客套、过程叙述、重复结论和无证据的形容词。
2. 一段或一条要点原则上只承载一个核心意思。出现两个可独立判断时拆分表达。
3. 每节先用标题、首句或 1–2 句短过渡给出中心判断。出现两项以上并列、递进或多层信息时，用一级 bullet 展开分论点；单个分论点包含多项证据、案例、解释或边界时，再用二级 bullet 展开。同层 bullet 保持同一划分维度和信息粒度。过渡、综合判断和需要连续叙述的短案例可以使用短段落，但不得形成连续长段，也不得用缺少承接关系的扁平 bullet 代替内容组织。
4. 出现至少三组同口径数字，或需要跨对象、跨时期、跨方案比较时，优先使用 Markdown 表格或清晰图示；少量关键数字可直接写入结论句。
5. 每个表图必须具备可独立理解的信息：明确标题、比较对象、指标、时间范围、单位、统计口径及必要图例或注释。缺失值使用“未提供”“不适用”或素材明确给出的状态，并说明原因；不得用 0 替代缺失值。
6. 表图中的每个数字必须原样来自素材。不得补数、插值、外推、换算未给出的数值或自行计算素材未明确允许的指标。
7. 遵守用户确认的页数或字数上限。用户未指定时，全文控制在三页或三千字以内；压缩时优先删除重复和低决策价值信息，不得删除关键事实、数据口径、限制条件或冲突说明。
8. 禁用“不是……而是……”式对举句和没有具体事实、动作或机制的术语空话；必要术语应承载明确含义。
9. 结论、条件、范围、比例、区间、频率、指代和归属必须无歧义。必要术语在首次出现时定义；重要不确定性同时说明判断边界、对决策的影响和验证动作。

## 二、生成流程

1. 读取用户确认的话题、重点及素材权重，提炼唯一的研究或决策问题。
2. 建立内部主张—证据清单，标记证据类型、口径、限制、冲突和素材缺口。
3. 将素材按同一分析维度分组，检查各组互斥性和整体覆盖度。
4. 先形成不超过三条的摘要判断，再为每条判断配置关键发现中的事实、数据、案例和边界。
5. 仅从已证实的问题、机制和约束推导启示；无法推导的部分明确留白并给出验证动作。
6. 将各节内容组织为“中心判断—分论点—证据、案例或边界”的层级，再用短段落和多级 bullet 呈现；数据密集或多组对比内容转换为表格或图示，并逐项核对数字及口径。
7. 完成全文后执行交付前自检。任何硬规则未通过，均不得交付。

## 三、交付前自检清单

### 证据检查

- [ ] 每个事实、数字、结论、归因、趋势、风险和建议均能定位到原始素材。
- [ ] 正文未出现素材之外的新事实、新数字或未经素材支持的推算。
- [ ] 所有转述均保持原主体、方向、范围、条件、口径和确定性。
- [ ] 冲突信息已并列说明，没有混用，也没有无说明地只取有利一方。
- [ ] 访谈、个案和单一模态证据已降低确定性并写明适用边界。
- [ ] 无法回答且影响决策的问题已说明可确认项、不可确认项和所需验证。
- [ ] 所有口径敏感数字均交代了理解所需的对象、时间、单位、基准及分子分母。

### 结构与逻辑检查

- [ ] 正文严格包含摘要、关键发现、启示三个模块，顺序正确且均有实质内容。
- [ ] 摘要不超过三条，均为独立核心判断，并按决策重要性排序。
- [ ] 关键发现逐项支撑摘要，没有摘要与正文脱节的结论。
- [ ] 每章标题或首句先给出中心判断，后续内容均用于支撑该判断。
- [ ] 全文围绕同一个研究或决策问题，章节之间存在清晰承接。
- [ ] 同层要点采用统一维度，边界互斥，并覆盖素材可支持的重要问题。
- [ ] 概念、指标、人群、时间和口径保持一致；所有切换均已说明。
- [ ] 素材中的重要差异、矛盾、反常、取舍和约束均已如实呈现。

### 洞察与覆盖检查

- [ ] 报告提炼了有多项证据支撑的模式或共性，没有停留在素材罗列。
- [ ] 原因或机制判断具有解释增量，并有素材支撑。
- [ ] 趋势、未来判断和风险已按证据强弱校准确定性。
- [ ] 异常或离群点已交叉验证、解释情境或明确标为待核实。
- [ ] 每项建议均对应前文问题或机制，并解释动作有效性的依据。
- [ ] 用户指定的全部模块、关键事实和关键结论均已覆盖。

### 表达与呈现检查

- [ ] 每段或每条原则上只表达一个核心意思，无重复铺垫和术语注水。
- [ ] 每节均能看出“中心判断—分论点—证据/案例/边界”的层级；两项以上并列或多层信息已使用多级 bullet，不存在连续长段堆叠或无承接的扁平 bullet 罗列。
- [ ] 数据密集或多组对比部分已优先使用 Markdown 表格或清晰图示。
- [ ] 每个表图均注明标题、对象、指标、时间、单位、口径及必要注释。
- [ ] 缺失值状态和原因明确，没有擅自补数或以 0 替代。
- [ ] 全文符合用户确认的篇幅；未指定时不超过三页或三千字。
- [ ] 未使用“不是……而是……”式对举句，未使用缺少具体事实、动作或机制的术语空话。
- [ ] 所有指代、归属、条件、比例、区间和不确定性均无歧义。

## 四、必要正反例

### 例 1：保持素材口径

正例：
> 2025 年第二季度，样本门店的复购率为 32%；该数字仅覆盖纳入本次调查的 40 家门店。

反例：
> 2025 年第二季度，公司整体复购率达到 32%，客户忠诚度显著提升。

反例问题：将样本门店扩大为公司整体，并增加了素材未必支持的趋势判断。

### 例 2：处理冲突

正例：
> 销售台账显示签约额同比增长 12%，财务确认收入同比增长 5%。两者确认时点不同，当前不能合并为单一增长结论；管理层需先统一观察口径。

反例：
> 业务收入同比增长 12%。

反例问题：忽略冲突口径，并只采用更有利的数字。

### 例 3：控制个案外推

正例：
> 两位渠道负责人均提到审批周期影响成交，提示审批可能是该渠道的转化阻力；现有访谈不足以判断其普遍程度，需结合全量周期数据验证。

反例：
> 审批周期是渠道转化下降的主要原因。

反例问题：将有限访谈升级为普遍且确定的因果结论。

### 例 4：素材不足时留白

正例：
> 当前可确认客诉量上升，但素材未提供订单基数，无法判断客诉率是否上升。该缺口会影响服务质量判断，需补充同期订单量及统一口径的客诉数据。

反例：
> 客诉率明显上升，应立即扩大客服团队。

反例问题：混淆客诉量与客诉率，并提出无法回溯到证据的动作。

### 例 6：形成可执行启示
