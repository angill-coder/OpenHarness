# Reflection：检查结构，再复核内容

仅执行 Reflection 时读取本文件。仍由 Memory Curator 完成，不新增成员；沿用其来源、提炼及压缩原则，不将主 Agent 的总结当作用户表达。Memory 关闭时不运行。

## 1. 检查并整理结构

重新读取当前 MEMORY、revision 和必要的相关文件，按 [模板](memory-template.md) 与 [统计脚本](memory-capacity.md) 的 `validate` 检查。旧名称、额外章节、索引和日志混入都是待整理项，不能只看目录存在就宣布符合规范。

逐段判断去向：经历归 L0，原子要求归 L1，已有变更记录归 `memory-history.md`；已在目标文件中完整保存的不重复创建。先核验或保存接收位置，再从 MEMORY 移除；旧库中只有这里保存的原话、依据和用户修改不能丢失。无法确认来源的旧叙述保留在历史迁移记录中并注明“旧文件记载、来源未核验”，不伪造用户原话、时间或授权。无法可靠迁移则保留原文、报告待处理，不强行清空。

格式整理不改变规则含义、Scope 或有效性，保留 ID、来源链、开关和已知版本；不回写原始 L0。内容是否应继续生效，另按下一步判断。

## 2. 复核、整理与压缩内容

检查 L2 是否有真实来源、长期适用性和明确 Scope，处理重复、冲突及确认过时的规则。一次任务要求、未获采纳的 Agent 推断或尚待确认的偏好，不因已经写在 MEMORY 就成为长期标准；有依据需要撤下时保留 L0/L1，在历史中记录原规则和原因。来源暂不可读时先报告待核验，不猜测、不仅因链接缺失就删除。

保留有依据的具体场景要求，不追求把所有规则泛化为 core。可以参考 `memory-stats.json` 的新鲜度和热度，沿用 Curator 的压缩原则；不要通过巨型 Rubric 规避 1,000 条上限。即使未超限，也可以清理确定的重复或失效内容，不强求每次有改动。

## 3. 检查遗漏与中断

按需复盘未处理或上次 Capture 中断的 Episodes，核验已有 captureId、L1 和 L2，避免重复处理。新证据仍按相同提炼门槛判断；可只补 L0/L1，不必晋升 L2，也不从 Loop 自动评测或版本选择反推偏好。不为整理而扫描所有已处理经历。

## 4. 校验与保存

对拟写 MEMORY 运行 `validate` 和 `check`，核验来源引用、迁移去向及规则前后差异。结构合格不代表语义正确，来源真实性与层级仍由 Curator 检查。保存前重新核对磁盘 revision 和内容；如有其他会话或用户修改，先合并最新内容，不按旧副本覆盖。

先保存需要补充的 L0/L1，再保存 MEMORY；本次全部实际内容/结构修改共用一次 revision 递增，随后追加历史、同步 L2 统计。纯格式整理不刷新规则的实质更新时间。读回确认结构、数量及本次来源链，完成后才更新 `lastReflectionAt`。

只更新复盘时间时返回 `MEMORY_REFLECTION_COMPLETED status=unchanged`，不加长篇检查日志、不新增历史。格式或内容有变化返回 `status=updated` 并简述实际改动。存在未解决项或写入失败返回 `MEMORY_REFLECTION_FAILED` 和已完成/待处理部分，不宣称全部完成；下次按已落盘的 revision 核验续做，不重复迁移或递增。
