# 清洗规则

改编自 OpenHarness `harness/data_quality_assets/structured_data_prompt.md` 及 `_data_audit.py` 的来源回查规则。保留证据原则，不移植其 Codex CLI、Human Report 质检和打分流程。

## 忠实于材料

- 先清洗、去重、合并和提炼，再输出论据；不逐段机械转录，不写报告或新增结论、建议。
- 覆盖有实质信息的数字、比较、趋势、机制、案例、反例、限制和异常；研究主题只影响顺序，不能删去不支持假设的事实。
- 数值保留对象、时间、样本、单位、分母和比较口径；缺失时说明缺失，不自行补全。百分比、百分点、均值和总量不能混用。
- 时间序列保留阶段变化、峰谷、反转和异常；材料没解释原因就不归因。汇总占比变化不等于同一个体迁移，不能在缺少面板/转移矩阵时写成“用户迁移”。

## 按素材处理

- 访谈：先还原“问题—回答—限定条件”，保留共性、差异、反例和少数意见。采访者的问题、寒暄、口头禅、无答案问题不形成 Evidence；问题中的数字也不能冒充被访者确认的事实。
- 逐字稿与整理稿：同义事实合并，并保留多个真实定位；独立来源数量按原始信源计算，不按文件份数计算。
- 表格：检查相关 Sheet、有效区域与指标族，保留分群、交叉差异、代表案例、异常和口径；不逐行照搬长表，也不能只读第一张 Sheet。
- PDF、Word、图片、Markdown、JSON：按同样原则处理，来源使用真实文件名及页码、段落、标题、表格或单元格；定位不明就如实说明，不猜页码。
- 用户指定的研究纪要/分析材料可以作为来源。分析师归纳无法恢复底层来源时用 `analyst_synthesis`，说明该限制；用户直接更正用 `user_statement` 并保留更正原文的定位。不要把候选报告、范文、Judge 输出或写作要求当作独立事实来源。

## 一条 Evidence 有多大

一条是可独立核验、可独立采用的论据或紧密相关事实组，通常 1–3 句。不同对象、时间、分群、指标口径或结论方向原则上拆开；同一主题连续问答和重复追问合并。不同事实可能被分别采用或判冲突时不要强行合并。

不设固定条数目标，不为凑条数保留噪声。公司、产品、时间与口径直接写进 `content`；不要另外堆叠公司索引、时间线、置信度评分、解析日志或大段原文。

## 缺口与更新

无法读取、无法定位、关键口径缺失和不能消解的冲突写入 `unresolved`。用户指出遗漏时，回到 source 重新抽取；不能复制“应该有的结论”作为新论据。更新前检查已有 Evidence，已充分覆盖就不重复新增。仅凭新信息无关、弱相关，不能删除旧有实质论据。
